## Спринт 5 · Стабілізація і демо

### SH-06 · Усі сервіси в Docker
**Розмір:** M · **Хто:** кожен для своїх сервісів

**Що зробити**
- Multi-stage `Dockerfile` для кожного сервісу: збірка в SDK-образі, запуск у легкому runtime-образі.
- Додати сервіси в `docker-compose.yml` з `profiles: ["apps"]`, щоб інфраструктура піднімалась окремо від застосунків.
- Адреси між сервісами — через імена контейнерів (`http://identity-service:8081`), а не `localhost`.

**Готово, коли**
- [ ] `docker compose --profile apps up --build` піднімає всю систему на чистій машині.

### SH-07 · Наскрізний сценарій
**Розмір:** M · **Хто:** обидва

**Що зробити**
- Скрипт або колекція `.http`-файлів, яка проходить: тестові токени для A і B → A вступає до закладу → створює проєкт → B подає заявку → A схвалює → дошка створилась → A створює картку з виконавцем B → B переносить її в Done → у портфоліо B видно 1 задачу.
- Кожен крок перевіряє відповідь, а не просто відправляє запит.

**Готово, коли**
- [ ] Сценарій проходить після `docker compose --profile apps up` без ручних дій.

**Підказка ментора:** через eventual consistency між кроками потрібні короткі повтори з таймаутом (наприклад, до 5 секунд), а не фіксований `sleep`.
